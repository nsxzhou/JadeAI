# 能力画像采用两层坐标（通用层 + 岗位族层）

Status: accepted

## 背景与决策

能力画像要能跨场次累积分数，前提是坐标轴稳定。旧实现里 6 种面试官各有独有维度，两次面试的维度不同，分数不可比，画像也就无从谈起。我们决定把评分坐标固定为两层：**通用层** 4 维（沟通表达 / 逻辑思维 / 抗压能力 / 学习能力）每场必测、跨岗位族可比；**岗位族层**由岗位族决定（招聘岗位族 3–4 维）。题型（`category`）与评分坐标（`dimension`）彻底解耦——「问什么」不等于「按什么打分」。

## Considered Options

- **沿用面试官自带维度**：不改数据模型，但两次面试分数不可比，画像不成立。否决。
- **单层扁平坐标系**：只在通用层上累积。跨岗位族可比，但「我的 Go 并发还是弱」这类具体结论无处安放，错题本失去坐标。否决。
- **纯 LLM 自由判定坐标**：判定会漂移，同一份回答两次跑出不同坐标，污染画像。否决。

## Consequences

- 新增维度必须落进两层坐标系之一，且 key 一旦沉淀不可改（改了历史分数就断链）。
- 老报告坐标不固定，读得到但不进画像。
- `DimensionConfig.weight` 只表评分口径，出题数量另设字段（见设计文档 §3.3）。
